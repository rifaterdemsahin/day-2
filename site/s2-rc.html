✅ Recommendations, best value first

  1. 🧾 Give the agent a small briefing instead of the full spec
    Saves ~30k tokens per run. Add a repo-root CLAUDE.md of about 1.5k tokens (standing rules, file map, facts live in short.json); the agent loads it automatically. Change the task prompt to read one named spec section only when needed.
  2. ✂️ Split MASTER_SPEC.md into files
    spec/rules.md, part-a-long.md, part-b-short.md, and generate the full file for reading. Move B7 out of the spec: the Iterations page already has it.
  3. 🧩 Split the site generator into one file per page
    pages/s2_x.py and so on. A note about one page then costs 1–2k tokens instead of 23k, and edits get less error-prone.
  4. 📊 Log the cost of every run
    claude -p --output-format json returns usage. Print tokens and cost in the RESULT block so you can measure what the changes save.
  5. 🚦 Route by size
    Small text edits to kilo (free) or a cheaper claude model, bigger changes to claude. The runner can pick from the note length, or you pick.
  6. 🤖 Auto-deploy on push
    A GitHub Action runs fly deploy on every push to main. Fits trunk-based development and removes the laptop from the deploy step. Needs a Fly token as a GitHub secret; keep it short-lived.
  7. 🧹 Stop committing site/ and the 22 root redirect pages
    Build site/ inside the Docker image. Diffs and patches get much smaller. Keep only the tiny GitHub Pages redirect.

🗄️ SQLite and React

  1. 🗄️ SQLite
    Not a token saver for the spec or the log: those are text the agent edits and git is the audit trail. It does help your review ticks and notes, which live in each browser's localStorage and reset on a new device or address. A small SQLite database on a Fly volume (about 1 GB, cheap) keeps them across devices and lets the agent ask for only the unresolved feedback (a few hundred tokens instead of a pasted dump). Cost: a small server and a volume instead of static nginx. Do it after items 1–4.
  2. ⚛️ React
    Not worth it: 23 mostly static pages, 0.08 s build. React adds a build chain and more code for the agent to read. If you want components, Astro (Markdown plus small interactive parts) fits better, but only if the Python generator becomes painful after splitting it. The notes panel and the sandbox can stay plain JavaScript.

🎬 For video production specifically

  • Make progress durable: clip, voice and render ticks should live in a file or database, not the browser. Add a per-clip status in short.json and sync it with the move-and-sync step.
  • The 🚀 button needs your laptop's runner to be running. To work without it, the whole job can run on the Sprite, which needs a repo-only GitHub token on it (giving up the current no-token safety). Only trade that if the laptop dependence hurts.
  • Keep Flow, Higgsfield and the Remotion render manual and local. The agent only speeds up the plan around them.
  • Reliability: run the live evals on a schedule and put the agent check (sprite_check.py) in the same run.
